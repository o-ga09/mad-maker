# 要求・要件・仕様

mad-maker の「何を作るか」をまとめたドキュメント。Issue（#2〜#12）に散らばっていた前提を、次の 3 層に整理する。

| 層 | ファイル | 書くこと | 主な読者 |
| --- | --- | --- | --- |
| 要求 | [01-needs.md](01-needs.md) | 誰の、どんな困りごとを、なぜ解決するか | オーナー |
| 要件 | [02-requirements.md](02-requirements.md) | アプリが満たすべき条件（機能・非機能）。ID で参照する | オーナー・Routine |
| 仕様 | [03-specification.md](03-specification.md) | 要件をどう実現するか（入出力、計算規則、操作、エラー） | Routine（実装・レビュー） |

## 運用ルール

- 正（Source of Truth）は Issue の完了条件。このドキュメントと Issue が食い違う場合は Issue を優先し、このドキュメントを直す PR を出す。
- 新しい Issue を書くときは、対応する要件 ID（`FR-xx` / `NFR-xx`）を本文に書く。
- 「未決定」と書かれた項目は、推測で実装しない。Issue で決めてから、このドキュメントに反映する。
